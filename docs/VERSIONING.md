# 버전 규칙

## 형식

- 버전은 `0.MINOR.PATCH`다. SemVer를 따르고 1.0 전 단계다.
- 태그는 `v<버전>`이다.

## 무엇을 올리나

버전은 PR마다 올리지 않는다. 지난 태그 이후 main에 쌓인 변경 중 가장 큰 것으로 정한다.

- MINOR (0.x.0): 새 기능이다. 새 화면, 패널, 메뉴, 새 설정, 새 에이전트 어댑터가 여기에 든다. 기존 동작을 바꾸거나 없애는 변경, 설정 파일과 hook 형식 변경도 MINOR다. 릴리스 노트의 "새로 더한 것"에 들어가는 항목이 하나라도 있으면 MINOR다.
- PATCH (0.x.y): 버그 수정과, 이미 있는 기능을 다듬는 작은 UI 개선이다. 예를 들어 입력창 기록에 위치 `3/12`를 표시하는 일이다. 노트에는 "고친 것"과 "다듬은 것"만 있다.
- 올리지 않음: docs, CI, 테스트, 리팩터만 바뀐 경우다.

## 언제 내나

- 사용자가 바로 필요로 하는 수정은 그때 PATCH로 낸다.
- 기능은 몇 개 모아서 MINOR 하나로 낸다. 기능 PR 하나당 MINOR 하나는 피한다.

## 1.0.0

- Windows와 macOS 설치 파일이 안정되고 설정·hook 형식을 유지하기로 정할 때 낸다.
- 그 뒤로는 호환이 깨지는 변경에 MAJOR를 올린다. 설정, hook, 저장 데이터 형식이 해당한다.

## 게시한 태그

- 게시한 태그는 되돌리지 않는다.
- 문제가 있으면 다음 PATCH로 고친다. 0.4.2를 revert했던 일이 있다.

## 올리는 파일과 절차

- `tauri.conf.json`, `Cargo.toml`(앱과 `hook/`), `package.json`과 두 lock 파일의 버전을 올린다.
- `README.md`를 지난 태그 이후의 변경(`git log v<이전 버전>..`)과 대조해 다시 쓴다. 새 기능은 "기능"에 넣고, 바뀌거나 없어진 동작은 고치고, 설치·Hermes 연결 방법이 바뀌었으면 함께 고친다. README에는 소개, 설치, 기능, 기여 방법, 라이선스만 둔다. 진행 상황, 단계표, 내부 문서 목록은 넣지 않는다.
- README 갱신은 버전을 올리는 릴리스 커밋에 함께 넣는다.
- `v<버전>` 태그를 push하면 태그 빌드가 초안 릴리스에 설치 파일을 붙인다.
- 확인 뒤 `gh release edit v<버전> --draft=false --latest`로 게시한다.
- 릴리스 노트는 `docs/releases/v<버전>.md`에 쓴다. 섹션은 새로 더한 것 / 다듬은 것 / 고친 것이다. 비는 섹션은 뺀다.
